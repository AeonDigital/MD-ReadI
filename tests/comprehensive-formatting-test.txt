# Teste Abrangente de Formatação MD-ReadI

## Como executar este teste

Este arquivo é um .txt propositalmente para evitar que o hook de pre-commit execute o formatter e destrua a formatação desejada para teste.

Para testar, copie o conteúdo deste arquivo para um arquivo temporário .md e execute:

```bash
cp tests/comprehensive-formatting-test.txt /tmp/test-formatting.md

for f in src/share/*.sh; do . "$f"; done
for f in src/readi/canonize/*.sh; do . "$f"; done
for f in src/readi/format/*.sh; do . "$f"; done
for f in src/readi/*.sh; do
  if [[ "$(basename "$f")" != "main_autoexec.sh" ]]; then
    . "$f"
  fi
done

shell_md_readi /tmp/test-formatting.md tests/comprehensive-formatting-test.output.md
# Depois abra 'tests/comprehensive-formatting-test.output.md' para conferir o resultado
```

### 2.2 Teste de Quebra de Linha em 80 Caracteres

Este parágrafo foi construído propositalmente para demonstrar como o formatter deve quebrar linhas no ponto mais próximo de 80 caracteres quando uma palavra inteira não couber no final da linha atual, conforme especificado na documentação do projeto.

Este outro parágrafo contém esta estrutura específica: "este paragrafo serve para demonstrar que, conforme a especificação, a quebra de linha deve ocorrer sempre a partir da linha 80 ou o mais perto disso caso uma palavra fique bem na 'linha' de quebra" - observar como o formatter vai quebrar isso.

Mais um exemplo: a palavra "configuração" aparece bem no meio desta frase artificial construída apenas para testar o comportamento exato da quebra de linha quando uma palavra chega perto do limite de oitenta caracteres.

Quando você usa `$variavel` em código inline, isso deve ser preservado.
